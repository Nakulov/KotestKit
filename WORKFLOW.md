# Как мы работаем

Памятка: что сказать Claude и что запустить самому. Подробности — в скиллах `.claude/skills/`.

## Цикл задачи

| Шаг     | Что сказать                                               | Что происходит                                                                                                                                                                                        |
|---------|-----------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Груминг | «давай погрумим …», «обсудим задачу …», «заведи задачу …» | Скилл `groom`: проблема → концепция → решения по одному → для задачи с API — API целиком → черновик задачи → после «ок» задача на доске в Groomed → самопроверка; холодное чтение — с вашего согласия |
| Сброс   | `/clear`                                                  | После груминга                                                                                                                                                                                        |
| Работа  | «берём в работу #N»                                       | Скилл `take`: ветка `task/<N>-…` от `dev`, In progress, для бага сначала падающий тест, изменения, проверка                                                                                           |
| Коммит  | «коммить»                                                 | Только после вашего согласия; затем PR в `dev`, In review                                                                                                                                             |
| Слияние | сливаете сами (squash), говорите «слил»                   | Claude переключается на `dev` и обновляет его                                                                                                                                                         |
| Сброс   | `/clear`                                                  | После PR                                                                                                                                                                                              |

Посреди работы не сбрасываем: договорённости, не записанные в задачу или память, теряются.

В `dev` можно попасть только через PR, и проверка `build` должна пройти.

## Полезные слова

- **«закругляемся»** — Claude записывает незаписанное: решения в задачу, план в заметку «текущая работа» в памяти — и
  одной строкой говорит, где что лежит. Говорите перед `/clear` или перед уходом.
- **Новая сессия** — `groom` и `take` первым шагом читают заметку «текущая работа», состояние ветки и задачу с
  комментариями; если ветка задачи уже есть, работа продолжается в ней. Тело задачи — действующее решение,
  комментарии — история: при расхождении действует тело.
- Темы, всплывшие по ходу, Claude предлагает завести отдельно в Backlog — сами в задачу не попадают.
- **Холодное чтение** — после груминга Claude может предложить проверить задачу агентом, который видит только её
  тело: что ему непонятно, то и дописывается в задачу. Запускается только с вашего согласия. Если после правок
  изменились API или разбивка на PR, Claude предложит второе чтение.

## Доска

[KotestKit](https://github.com/users/Nakulov/projects/9): Backlog → Groomed → In progress → In review → Done.

```sh
tools/board.sh status <N> groomed              # backlog, groomed, in-progress, in-review, done
tools/board.sh issue "<заголовок>" <метка> body.md   # печатает номер
tools/board.sh sub <эпик> <N>
```

Метки: `bug`, `enhancement`, `documentation`, `build`, `process`, `epic`. Этапы — вехи репозитория, приоритет — поле
Priority на доске (P0, P1, P2).

## Команды репозитория

```sh
./gradlew build   # сборка и тесты
```
