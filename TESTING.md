# Как мы пишем тесты

## Правила

- Тесты пишутся только как спеки Kotest.
- Внешние спеки на `StringSpec`. `BehaviorSpec` только там, где сама проверка касается Given/When/Then.
- Спека соответствует файлу, где объявлен публичный вызов, пакет тот же: `transformation/TransformationExt.kt` →
  `transformation/TransformationExtSpec.kt`, `DataExt.kt` → `DataExtSpec.kt`. Спека заводится, когда на файл появляются
  первые тесты. Вызов вместе с `.config(...)` проверяется там же.
- Файлы без вызовов для пользователя (фабрики, DSL-классы, конфиги, например `TransformationTestFactory.kt` и
  `ConfigExt.kt`) своих спек не получают, они проверяются через публичные вызовы.
- Тестовые данные, только если нужны, лежат в `<Имя>SpecData.kt`. Именованных классов-спек там нет: такой класс Kotest
  запустит как настоящий тест.
- Что произошло при прогоне, проверяем через `runStringSpec` и `runBehaviorSpec`. Спеку для прогона описываем в их
  лямбде, а не отдельным классом.
- Для бага сначала падающий тест. Зелёная спека без единого теста ничего не доказывает.

## Проверка прогона спеки

`runStringSpec` и `runBehaviorSpec` из `src/test/kotlin/io/github/nakulov/kotestkit/testing/RunSpec.kt` прогоняют спеку
из лямбды и возвращают отчёт: `tests` и `specError`. Сами они ничего не проверяют, проверки пишутся матчерами Kotest.
Если сломался движок Kotest, помощник бросает его ошибку: такому отчёту нельзя верить.

```kotlin
"вызов создаёт один успешный тест" {
    val run = runStringSpec { "t" { } }

    run.tests.single().result.isSuccess shouldBe true
}
```

Как ведёт себя прогон (проверено на Kotest 6.2.6):

- Ноль тестов для Kotest не ошибка: спека `Success`, ошибок движка нет. Ловится через `.single()` или `shouldHaveSize`.
- Исключение в теле спеки: 0 тестов и заполненный `specError`.
- Отключённый тест: приходит как `Ignored`, `config.enabled == false`.
- Родитель остаётся `Success`, когда упал вложенный тест: результат смотрим у самого `Then`.
- Падение внутреннего теста не роняет внешний, внутренние тесты не попадают в его отчёт.
