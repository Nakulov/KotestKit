Новый вызов `shouldRoundTripTest` в `kotestkit-serialization`: образец JSON сам служит эталоном, ожидаемый DTO не нужен. Старые вызовы не менялись, переход с 2.1.0 ничего не требует.

Подробности и граница проверки описаны в [README](https://github.com/Nakulov/KotestKit/blob/v2.2.0/README.md#образец-без-ожидаемого-значения).

## Подключение

```kts
dependencies {
    testImplementation("io.github.nakulov:kotestkit-serialization:2.2.0")
}
```

## Новое

- `shouldRoundTripTest<T>(resource)` внутри `withJson`: разбирает образец `Json` группы, записывает результат полностью
  (копией этого `Json` с `encodeDefaults = true` и `explicitNulls = true`) и проверяет, что образец — подмножество записи.
  Значения по умолчанию и явные `null` в образце не дают ложного падения, лишние ключи записи допускаются, `1` и `1.0` равны.
  Имя теста: `dto/user/full.json <-> UserDto`.
- `shouldRoundTripTest(resource, serializer)` — то же с явным сериализатором корня, когда `serializer<T>()` не даёт
  нужного правила. Имя теста заканчивается `serialName`.
- Полиморфный корень берёт сериализатор из `serializersModule` группы.
- При падении отчёт называет путь поля, например `At 'vertical.gap' expected 's' but was 'zero'`, первой в стеке идёт
  строка вызова в вашей спеке.

```kotlin
class UserSamplesTest : BehaviorSpec({
    withJson {
        shouldRoundTripTest<UserDto>("dto/user/full.json")
        shouldRoundTripTest<UserDto>("dto/user/without_nickname.json")
    }
})
```
