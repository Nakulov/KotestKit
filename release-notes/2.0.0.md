Первый выпуск под именем KotestKit. Все изменения ниже указаны относительно `com.simple.kotest:skotest:1.0.1`.

Настройка и стандарт формы тестов описаны в [README](https://github.com/Nakulov/KotestKit/blob/v2.0.0/README.md).

## Что менять в тестах

### Один вызов вместо builder

`.config(...)` и классы `TransformationTestDsl*`, `ShouldThrowTestDsl` убраны. Лямбда теперь обязательна, настройки передаются через `options`. `transformationTest` называется `shouldReturnTest`, параметры `expectedResult` и `transformBlock` стали `expected` и `block`.

```kotlin
// было
transformationTest(3, 1).config { it + 2 }
transformationTest(3, 1).config(testName = "сложение", blockingTest = true) { it + 2 }
shouldThrowTest<IllegalStateException>().config(enabled = false) { error("x") }

// стало
shouldReturnTest(3, 1) { it + 2 }
shouldReturnTest(3, 1, options = TestOptions("сложение", TestConfig(blockingTest = true))) { it + 2 }
shouldThrowTest<IllegalStateException>(TestOptions(config = TestConfig(enabled = false))) { error("x") }
```

Раньше `transformationTest(1)` без `.config` компилировался и не создавал теста. Теперь это ошибка компиляции. Если такие вызовы были, при переходе они станут настоящими тестами и могут упасть.

### `Lazy` убран

```kotlin
// было
transformationTest(lazy { expected() }, 1).config { it + 2 }

// стало
shouldReturnTest(expected(), 1) { it + 2 }
```

### Настройки доходят до Kotest как написаны

Раньше `blockingTest` включал `coroutineDebugProbes`, `coroutineTestScope` включал `blockingTest`, а `extensions` терялись. Теперь `TestConfig` передаётся целиком. Тесты с этими настройками начнут работать по написанному, их стоит перепроверить.

### `withData` убран

Параметризованные тесты пишутся через `withGivens`, форма вызова та же. Блок теперь выполняется внутри `given`, поэтому вложенный `given` убирается, а `when` и `then` остаются.

```kotlin
// было
withData(nameFn = { "вход: ${it.arg2}" }, case(arg1 = 3, arg2 = 1)) { expected, input ->
    transformationTest(expected, input).config { it + 2 }
}

// стало
withGivens(nameFn = { "вход: ${it.arg2}" }, case(arg1 = 3, arg2 = 1)) { expected, input ->
    shouldReturnTest(expected, input) { it + 2 }
}
```

### Вызовы в контейнерах

- В любом контейнере любого стиля вызов создаёт один обычный тест. Раньше он падал при запуске или обрывал остальные проверки контейнера.
- Внутри теста вызов не компилируется, в том числе `shouldReturnTest` и `shouldThrow*Test` внутри `then`.
- `withGivens` работает только в корне `BehaviorSpec`, вложенный вызов не компилируется.

### Имена тестов

Имена по умолчанию теперь показывают значения. Если на старые имена опираются фильтры или отчёты, их нужно обновить.

| Вызов | Было | Стало |
|---|---|---|
| `shouldReturnTest(3) { 3 }` | `transformation to Int` | `expected 3` |
| `shouldReturnTest(99, "ab") { … }` | `transformation String to Int` | `"ab" -> 99` |
| `shouldThrowTest<IllegalStateException> { … }` | `should throw IllegalStateException` | `throws IllegalStateException` |
| `shouldThrowExactlyTest<IllegalStateException> { … }` | `should throw IllegalStateException exactly` | `throws exactly IllegalStateException` |
| `shouldThrowWithMessageTest<IllegalStateException>("boom") { … }` | `should throw IllegalStateException with message "boom"` | `throws IllegalStateException: "boom"` |

## Новое

- В публикации есть sources: код и документация библиотеки видны в IDE.
- `block` у `shouldThrow*Test` получает `TestScope`.
- При падении первой в стеке идёт строка вызова в вашей спеке.
